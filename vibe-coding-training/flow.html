전체 흐름 한 장

말로 시킨 것이 남이 쓰는 프로그램이 되기까지  |  읽는 데 약 10분

AI에게 시켜서 무언가를 만들어 본 경험은 이미 있으실 겁니다. 그런데 "내 컴퓨터에서는 되는데 다른 사람은 못 쓴다"에서 멈추는 경우가 많습니다.
이 문서는 그 사이에 무엇이 있는지를 한 장으로 정리합니다. 뒤의 문서들은 모두 이 그림의 한 칸을 자세히 본 것입니다.

1 일곱 단계

앞의 세 단계는 이미 해 보신 부분이고, 이번 연수는 ④부터 ⑦까지를 다룹니다.

① 요청
무엇을 만들지 AI에게 말한다
→
② 생성
내 PC의 폴더에 파일이 생긴다
→
③ 확인
내 PC에서 열어 보고 고친다
→
④ 저장
되돌아올 지점을 남긴다 (git)
⑤ 올리기
코드를 GitHub에 올린다
→
⑥ 배포
프로그램이 돌 자리를 정한다
→
⑦ 접속
누가 어디서 쓰는지 확인한다
→
다시 ①로
고칠 것이 생기면 처음부터 반복
단계이때 일어나는 일자세한 문서
①②③ 만들기 AI가 내 폴더의 파일을 만들고 고칩니다. 결과는 내 PC에만 있습니다. 별도 자료로 준비 중. 도구는 클로드 코드 vs 코덱스
④ 저장 지금 상태에 이름표를 붙여 둡니다(커밋). AI가 망쳐도 이 지점으로 돌아올 수 있습니다. 웹앱 배포 따라하기 2장
⑤ 올리기 저장한 것을 GitHub로 보냅니다(푸시). 코드의 사본이 인터넷에 생깁니다.
⑥ 배포 프로그램이 실제로 도는 자리를 정합니다. 온라인서버, 내 PC, 교내 서버 중 하나입니다. 웹앱 배포 · 데스크톱 앱 배포 · Vercel과 Cloudflare
⑦ 접속 쓰는 사람과 프로그램 사이에 무엇이 가로막는지 확인합니다. 배포 상황 10가지

2 헷갈리는 세 쌍

같은 것처럼 들리지만실제로는
저장(④) 과 올리기(⑤) 저장은 내 PC 안에 기록을 남기는 것이고, 올리기는 그 기록을 GitHub로 보내는 것입니다. 저장만 하고 올리지 않으면 PC가 고장 났을 때 함께 사라집니다.
올리기(⑤) 와 배포(⑥) GitHub에 올라간 것은 코드 보관함일 뿐, 아직 누구도 프로그램을 쓸 수 없습니다. 배포는 그 코드를 어딘가에서 실행시키는 일입니다.
배포(⑥) 와 접속(⑦) 배포가 끝났어도 쓰는 사람 쪽에서 막히면 열리지 않습니다. 학교망 차단 필터가 대표적입니다. 배포한 사람 화면에서 되는 것과 쓰는 사람 화면에서 되는 것은 따로 확인합니다.

3 배포 전에 답할 네 가지 질문

⑥에서 어디에 배포할지는 취향이 아니라 아래 네 질문의 답으로 정해집니다. AI에게 배포를 시킬 때도 이 네 가지를 먼저 말해 주면 결과가 달라집니다.

1. 누가 쓰는가 — 나 혼자 / 교내 선생님 / 학생 / 학교 밖 사람
2. 프로그램은 어디서 도는가 — 내 PC / 교내 서버 / 온라인서버
3. 데이터는 어디에 쌓이는가 — 쌓이지 않음 / 내 PC / 교내 서버 / 온라인 DB
4. AI 모델을 쓴다면 어디서 도는가 — 쓰지 않음 / AI 회사 서버 / 내 PC나 교내 서버
