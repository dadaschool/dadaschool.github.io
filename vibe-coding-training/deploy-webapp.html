웹앱 배포 따라하기

GitHub → Vercel  |  소요 시간 참고: 40분 내외

지금까지는 내 컴퓨터 안에서만 실행되는 결과물을 만들었습니다. 이 문서는 그 결과물에 인터넷 주소를 달아서, 다른 사람도 브라우저로 바로 볼 수 있게 만드는 과정입니다.
핵심 흐름은 딱 두 단계입니다: ① GitHub에 코드 올리기 → ② Vercel과 연결하기. 한 번 연결해두면 이후에는 코드를 고쳐서 GitHub에 다시 올리기만 해도 자동으로 재배포됩니다.

시작하기 전에

  • GitHub 계정 — 없다면 github.com/signup에서 이메일로 무료 가입
  • Vercel 계정 — vercel.com/signup에서 Continue with GitHub로 가입하면 계정을 따로 만들 필요 없이 바로 연결됨
  • git — 윈도우는 Git for Windows를 설치해 두세요. (아래 방법 C로 올린다면 없어도 됩니다)
  • 배포할 프로젝트 폴더 — 예전에 AI 도구로 만들어 둔 웹 결과물 폴더. 없다면 예제 파일(수업 타이머)을 열어 Ctrl+S로 새 폴더에 index.html이라는 이름으로 저장해 쓰세요.
더블클릭으로 열리는 결과물이면 그대로 올리면 됩니다. 고칠 것이 없습니다. 웹앱으로 배포하면 쓰는 사람은 파일을 받을 필요 없이 주소만 누르면 되고, 켜 두는 일은 서비스가 맡습니다.
⚠️ 올리기 전에 폴더 안을 먼저 보세요. GitHub 저장소는 인터넷에 공개될 수 있습니다.
아래 세 가지가 폴더에 있으면 올리지 않습니다. 한 번 올라간 것은 지워도 기록에 남습니다.
  • 비밀 키 — API 키, 비밀번호, .env 파일
  • 학생·교직원 자료 — 명단, 사진, 제출물, 성적
  • 정답·평가 자료 — 학생이 보면 안 되는 것
올리지 않을 파일은 .gitignore라는 파일에 이름을 적어 둡니다. AI에게 "올리면 안 되는 파일이 있는지 확인하고 .gitignore를 만들어줘"라고 먼저 요청하세요.
연습 단계에서는 저장소를 만들 때 Private을 고르는 것도 방법입니다. Vercel은 Private 저장소도 연결할 수 있습니다.

2 코드를 GitHub에 올리기

🤖 방법 A · AI에게 시키기 추천

클로드 코드/코덱스에게 자연어로 요청. 명령어를 몰라도 됩니다.
⌨️ 방법 B · 직접 명령어

git 명령어를 순서대로 복사-붙여넣기.

AI 도구도 git도 준비되지 않았다면 방법 C · 웹사이트에서 올리기로 가세요.

방법 A · AI에게 시키기

먼저 github.com/new에서 빈 저장소(Repository)를 하나 만들어 주세요. 이름만 정하고 Add a README 체크는 하지 말고 Create repository를 누르면 됩니다. 저장소를 만들면 주소(예: https://github.com/내아이디/저장소이름.git)가 화면에 보입니다.

그 다음 클로드 코드나 코덱스 입력창에 아래 문장을 붙여넣으세요. 여기에주소 부분만 방금 만든 저장소 주소로 바꿔주세요.

요청 예시
이 프로젝트를 git으로 초기화하고, https://github.com/여기에주소.git 저장소에 올려줘
중간에 파일을 추가하거나 명령을 실행해도 될지 물어보면 승인(예)을 눌러주세요.
완료되면 GitHub 저장소 페이지를 새로고침해서 내 파일들이 올라왔는지 확인하면 됩니다.

방법 B · 직접 명령어로 올리기

프로젝트 폴더에서 터미널을 연 뒤, 아래 명령을 순서대로 붙여넣고 하나씩 엔터를 치세요.

1 · 초기화 + 커밋
git init
git add .
git commit -m "첫 커밋"

github.com/new에서 빈 저장소를 만들고, 화면에 나오는 주소를 복사해 아래 명령의 여기에주소 자리에 넣어주세요.

2 · 저장소 연결 + 올리기
git remote add origin https://github.com/여기에주소.git
git branch -M main
git push -u origin main
⚠️ GitHub 로그인 창이 뜰 수 있습니다.
브라우저 창이 열리면 GitHub 계정으로 로그인하고 권한을 허용해 주세요.

방법 C · 웹사이트에서 올리기 (AI 도구·git 없이)

github.com/new에서 저장소를 만든 뒤, 화면의 uploading an existing file을 눌러 폴더 안의 파일을 끌어다 놓고 Commit changes를 누릅니다.
⚠️ 이 방법은 .gitignore를 보지 않습니다. 끌어다 놓은 것이 전부 올라가므로, 예제 파일처럼 올려도 되는 것만 든 폴더에서만 쓰세요.
학교망에서 git push가 인증서 오류로 막히면 다른 인터넷(테더링)으로 바꿔 올리거나, 방법 C처럼 브라우저로 올리면 됩니다. 브라우저는 학교망에서도 대개 정상입니다.

3 Vercel에 연결해서 배포하기

🖱️ 방법 A · 대시보드 클릭 추천

웹사이트에서 클릭만으로 연결. 터미널이 필요 없습니다.
⌨️ 방법 B · 터미널(CLI)

명령어로 배포. 이후 자동화에 익숙해지고 싶다면.

방법 A · 대시보드에서 배포하기

vercel.com/new에 접속해서 (GitHub 계정으로 로그인한 상태) Import Git Repository 목록에서 방금 올린 저장소를 찾아 Import를 누르세요.
설정 화면은 대부분 그대로 두고 Deploy 버튼만 누르면 됩니다. 잠시 후 배포가 끝나면 내프로젝트.vercel.app 형태의 주소가 발급됩니다.

방법 B · 터미널(CLI)로 배포하기

이 방법은 Node.js가 설치돼 있어야 합니다. 터미널에 node -v를 쳐서 버전 번호가 나오는지 먼저 확인하세요.

1 · Vercel CLI 설치
npm i -g vercel
2 · 로그인
vercel login

프로젝트 폴더 안에서 아래 명령을 실행하면 질문 몇 가지가 나옵니다. 특별한 이유가 없다면 기본값(엔터)으로 진행하면 됩니다.

3 · 배포
vercel

테스트 배포가 잘 됐다면, 아래 명령으로 정식 주소(프로덕션)로 올립니다.

4 · 정식 배포
vercel --prod

4 배포 확인하기

발급된 주소로 접속해서 실제로 화면이 뜨는지 확인하세요.
이후로는 코드를 고치고 방법 A/B로 다시 GitHub에 올리기(push)만 하면, Vercel이 자동으로 새 버전을 다시 배포합니다. 매번 새로 연결할 필요가 없습니다.
⚠️ 학교망에서도 열리는지 따로 확인하세요.
vercel.app 주소가 학교 차단 필터에 걸려 있는 경우가 있습니다. 수업에 쓸 계획이라면 교사 PC와 학생 기기 양쪽에서 미리 열어 보세요. 이유는 배포 상황 10가지의 10번에 있습니다.

심화 개념 실습 없이 개념만

데이터베이스가 필요하다면

내 앱에 "저장해야 할 데이터"가 있는지 먼저 생각해 보세요.

  • 방문자 수를 세고 싶다, 게시판에 글이 쌓여야 한다, 로그인 기능이 있다 → 데이터베이스(DB) 필요
  • 버튼을 누르면 그 자리에서 계산만 해주는 앱 → 필요 없음
데이터베이스는 "앱이 꺼졌다 켜져도, 다른 사람이 접속해도 사라지지 않는 저장 공간"입니다.
무료로 붙일 수 있는 대표적인 선택지로 Neon, Supabase(Vercel과 바로 연동), Cloudflare D1이 있습니다. 실제 연결은 AI에게 "이 프로젝트에 데이터베이스를 연결해줘"라고 요청하면 필요한 설정을 대신 진행해 줍니다.
⚠️ 개인정보는 넣지 마세요. 학생 이름·연락처 같은 민감한 정보는 연수용 데모 앱에 입력하지 않는 것이 안전합니다.

커스텀 도메인과 Cloudflare

Vercel이 기본으로 주는 내프로젝트.vercel.app 주소만으로도 배포는 이미 끝난 것입니다. 아래는 "원하는 주소(도메인)를 따로 쓰고 싶을 때"를 위한 참고 개념입니다.

  • 도메인 연결(DNS) — 예를 들어 my-project.com처럼 원하는 주소를 구매해서 Vercel 사이트에 연결하고 싶을 때, 그 주소의 "안내판" 역할을 하는 서비스가 필요합니다. Cloudflare가 이 역할로 가장 널리 쓰입니다.
  • (대안) Cloudflare 자체를 호스팅으로 사용 — Vercel 대신 Cloudflare Pages/Workers에 직접 배포하는 방법도 있고, 이 경우 Cloudflare D1(데이터베이스)까지 한 생태계 안에서 해결할 수 있습니다.
오늘은 Vercel 기본 주소로 배포하는 것까지만 실습합니다. 커스텀 도메인·Cloudflare 연결은 필요하신 분들을 위한 참고 개념으로만 남겨둡니다.
두 서비스가 각각 무엇을 맡는지 더 자세히 보려면 Vercel과 Cloudflare, 뭐가 다른가요? 문서를 참고하세요.

잘 안 될 때

이런 증상이면이렇게 해보세요
GitHub push 시 권한 오류 브라우저 로그인 창에서 권한 허용을 눌렀는지 확인하고, 저장소 주소(URL)를 다시 확인해 보세요.
Vercel에서 내 저장소가 목록에 안 보임 Vercel 계정과 GitHub 계정이 같은 계정으로 연결됐는지 확인하세요. (Import Git Repository 화면에서 "Adjust GitHub App Permissions" 클릭)
Deploy는 됐는데 빈 화면 / 오류 화면 Vercel 프로젝트 화면의 Deployments → 최근 배포를 눌러 빌드 기록(Build Logs)의 오류 메시지를 확인하고, 그 메시지를 그대로 AI에게 붙여넣어 고쳐달라고 요청하세요. 기록이 깨끗하면 배포된 주소에서 F12 → Console의 빨간 글씨를 붙여넣습니다.
CLI에서 vercel: command not found 터미널을 완전히 닫았다가 새로 열고 1번 명령을 다시 실행해 보세요.
그래도 안 될 때 오류 화면을 캡처해서 연수 담당 채팅방에 올려주세요.
