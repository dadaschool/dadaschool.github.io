2지역 LLM이란?

LLM(Large Language Model, 대규모 언어 모델)은 많은 글을 학습해 사람처럼 글을 읽고 쓰는 AI입니다. 챗GPT, 제미나이, 클로드가 모두 LLM입니다.
지역 LLM(로컬 LLM)은 이런 모델을 회사 서버가 아니라 내 컴퓨터 안에서 실행하는 것을 말합니다. 모델 파일을 내려받아 두면 인터넷이 끊겨도 동작합니다.

구분클라우드 AI (챗GPT·제미나이·클로드 등)지역 LLM (LM Studio + 큐웬)
어디서 돌아가나회사의 대형 서버내 노트북의 CPU·메모리
내가 입력한 글인터넷으로 회사 서버에 전송됨노트북 밖으로 나가지 않음
인터넷항상 필요모델을 내려받을 때만 필요
비용무료 한도 또는 유료 구독무료 (전기·노트북 성능만 사용)
글의 품질매우 높음 (모델이 매우 큼)모델 크기에 따라 다름. 4B 모델은 짧고 단순한 글에 적합
속도빠름GPU 없는 노트북은 느림 (글 한 편에 수십 초~수 분일 수 있음)
최신 정보·검색검색 기능이 있는 경우가 많음없음. 학습한 시점까지의 지식만 있음

학교 업무에서 지역 LLM이 어울리는 일 / 어울리지 않는 일

어울리는 일

  • 학생 정보가 섞인 자료로 초안 쓰기 — 성적 분석 피드백, 생기부 초안의 뼈대
  • 정해진 형식으로 짧은 글을 반복해서 쓰기 — 학생 125명분 문장 초안
  • 문장 다듬기 — 문체 바꾸기(~함, ~임), 맞춤법, 요약
  • 채점 기준표·발문 아이디어 초안
  • 인터넷이 불안정한 곳(출장지·체험학습)에서의 간단한 글쓰기

어울리지 않는 일

  • 사실 확인이 중요한 질문 — 법령, 최신 지침, 학교 일정 (지어낼 수 있음)
  • 긴 문서 전체를 정확히 분석하기 (작은 모델은 긴 글을 놓치기 쉬움)
  • 복잡한 계산 — 숫자는 파이썬·엑셀로 계산하고 AI에게는 글만 맡기기
  • 빠른 응답이 필요한 수업 중 실시간 활용
  • 최종본 — 어떤 AI든 결과는 초안이며 교사가 확인해야 함
⚠️ 지역 LLM이어도 지켜야 할 것
지역 LLM은 입력이 인터넷으로 나가지 않을 뿐, 틀린 내용을 그럴듯하게 쓰는 문제(환각)는 똑같이 있습니다. 또 노트북 자체가 분실·공유되면 그 안의 자료가 위험해집니다. 개인정보 수칙은 22장을 보세요.

3지역 LLM 핵심 용어와 종류

LM Studio에서 모델을 고를 때 아래 용어가 계속 나옵니다. 모델 이름 Qwen3-4B-GGUF Q4_K_M을 읽을 수 있으면 충분합니다.

모델 (Model)

예: Qwen3, Llama, Gemma

학습이 끝난 AI 본체. 파일 하나(또는 몇 개)로 되어 있습니다. 큐웬(Qwen)은 알리바바의 Qwen 팀이 공개한 모델로, Qwen3는 2025년 4월에 Apache 2.0 라이선스(상업적 이용도 허용되는 공개 라이선스)로 나왔습니다.

파라미터 (B)

예: 4B = 약 40억 개

모델이 학습한 숫자(가중치)의 개수. 클수록 대체로 똑똑하지만 더 크고 느립니다. Qwen3는 0.6B·1.7B·4B·8B·14B·32B 등이 있습니다. CPU 노트북에는 4B가 알맞습니다.

양자화 (Quantization)

예: Q4_K_M, Q8_0

숫자를 더 적은 자리로 줄여 파일을 작게 만드는 방법. Q 뒤 숫자가 작을수록 작고 빠르지만 품질이 조금 떨어집니다. Q4_K_M은 크기와 품질의 균형이 좋아 널리 쓰이는 선택입니다.

GGUF

예: Qwen3-4B-Q4_K_M.gguf

CPU에서도 돌리기 좋게 만든 모델 파일 형식. LM Studio는 윈도우에서 주로 이 형식을 씁니다. 이름에 GGUF가 있는 것을 고르면 됩니다.

토큰 (Token)

예: 한글 한 글자 ≈ 1토큰 안팎

AI가 글을 처리하는 단위. 속도는 초당 토큰 수(tok/s)로 표시합니다. 같은 노트북이라도 긴 글일수록 오래 걸립니다.

컨텍스트 (Context)

예: 4096 토큰

AI가 한 번에 기억하며 읽을 수 있는 글의 길이(질문+답 합계). 길게 늘리면 메모리를 더 씁니다. 긴 문서를 통째로 넣으면 앞부분을 잊을 수 있습니다.

생각 모드 (Thinking)

예: 질문 끝에 /no_think

Qwen3는 답하기 전에 속으로 생각하는 과정(<think>)을 쓸 수 있습니다. 정확해질 수 있지만 훨씬 오래 걸립니다. 질문 끝에 /no_think를 붙이면 생각을 건너뛰도록 요청할 수 있습니다.

온도 (Temperature)

예: 0.2 차분함 ~ 1.0 다양함

답의 다양성 조절값. 낮으면 같은 질문에 비슷한 답, 높으면 매번 다른 답. 업무 문서는 0.2~0.5 정도가 무난합니다.

환각 (Hallucination)

예: 없는 법령 조항을 지어냄

AI가 사실이 아닌 내용을 그럴듯하게 쓰는 현상. 작은 모델일수록 잦습니다. 사실·숫자·이름은 반드시 확인하세요.

CPU · GPU · RAM

예: RAM 16GB, GPU 없음

모델은 실행되는 동안 RAM(메모리)에 올라갑니다. 그래픽카드(GPU)가 있으면 빨라지지만 없어도 CPU로 돌아갑니다. 이 연수는 GPU 없는 노트북을 기준으로 합니다.

노트북권장 시작 모델
RAM 16GB, GPU 없음 (이 연수 기준)Qwen3 4B, Q4_K_M (약 2.5GB). 여유가 있으면 8B Q4_K_M(약 5GB)도 시험해 볼 수 있습니다.
RAM 8GB더 작은 모델(예: 1.7B)이 필요할 수 있습니다. 이 연수에서는 확인하지 못했습니다. 확인 필요
GPU(그래픽 메모리 4GB 이상) 있음LM Studio가 GPU를 쓰면 빨라집니다. LM Studio 공식 문서는 GPU 메모리 4GB 이상을 권장합니다.

새 버전 모델 — 지역 LLM은 새 모델이 자주 나옵니다(예: Qwen3 다음 버전인 Qwen3.5). 이 연수와 활용 예시 프로그램은 Qwen3 4B로 맞춰 만들었습니다. 다른 모델도 같은 방식으로 쓸 수 있지만, 결과 품질과 속도는 직접 확인해 보세요. 생각 모드를 끄는 /no_think는 큐웬 전용이라 다른 계열에서는 듣지 않을 수 있습니다.

4LM Studio란?

LM Studio는 지역 LLM을 쉽게 쓰도록 만든 무료 데스크톱 프로그램입니다. 명령어 없이 화면에서 클릭으로 모델을 받고 대화할 수 있습니다.

① 모델 찾기·내려받기 (Discover)

  • Hugging Face(공개 AI 모델 저장소)의 모델을 검색해 내려받습니다.
  • 노트북 사양에 맞는지 표시해 주기도 합니다.

② 채팅 (Chat)

  • 챗GPT처럼 대화 창에서 바로 써 봅니다.
  • 모델 비교, 프롬프트 연습에 좋습니다.

③ 로컬 서버 (Developer)

  • 다른 프로그램이 이 노트북의 AI를 쓸 수 있게 창구를 엽니다.
  • 주소: http://localhost:1234

④ 모델 관리 (My Models)

  • 받은 모델 목록 확인, 지우기.
  • 모델 파일은 크기가 커서 저장 공간을 확인하며 관리합니다.

로컬 서버와 API — 프로그램끼리 대화하는 창구

사람은 채팅 창으로 AI와 대화하지만, 프로그램은 API(약속된 주소와 형식)로 AI와 대화합니다. LM Studio의 로컬 서버는 OpenAI(챗GPT 회사)의 API와 같은 형식을 따릅니다. 그래서 챗GPT용으로 만든 프로그램도 주소만 바꾸면 지역 LLM을 쓸 수 있습니다.

포트(1234) — 한 컴퓨터 안의 여러 창구를 구분하는 번호입니다. 건물 주소(localhost)의 호수라고 생각하면 됩니다. LM Studio는 1234번, 활용 예시 프로그램 화면은 8501번을 씁니다.

6데이터베이스(DB)와 SQLite

데이터베이스(DB)는 자료를 정해진 표 형태로 저장하고, 필요한 자료를 빠르고 정확하게 찾아 주는 저장소입니다. 엑셀과 비슷해 보이지만 목적이 다릅니다.

구분엑셀데이터베이스
주 용도사람이 보고 고치는 문서프로그램이 읽고 쓰는 저장소
규칙아무 칸에 아무 값이나 입력 가능열마다 형식이 정해짐. 규칙을 어기면 저장 거부
중복 막기사람이 확인기본 키로 자동으로 막음 (예: 같은 학번·같은 문항 두 번 저장 불가)
찾기·모으기필터, 피벗SQL이라는 질문 문장으로 찾고 계산
여러 표 연결VLOOKUP 등으로 수동학번·시험번호 같은 열로 표끼리 연결

DB의 기본 단어

테이블(표)

예: scores(점수) 표

엑셀의 시트 하나와 비슷합니다. 한 DB 안에 여러 테이블이 있습니다.

행(레코드)과 열(필드)

예: 학번 10101의 문항1 점수 4점 = 한 행

행은 자료 한 건, 열은 항목(학번, 문항, 점수)입니다.

기본 키(Primary Key)

예: (학번, 문항) 조합은 하나뿐

행을 하나로 구별하는 열. 같은 값이 두 번 들어가지 못하게 막아 자료가 꼬이지 않습니다.

SQL

예: SELECT AVG(score) FROM scores

DB에 질문하는 문장. "점수 표에서 평균을 구해 줘"를 정해진 문법으로 쓴 것입니다.

SQL 예시 (읽기만 해 보세요) — "문항별 평균 점수와 학생 수를 구해 줘"
SELECT item, AVG(score), COUNT(*)
FROM scores
GROUP BY item;

SQLite — 파일 하나짜리 데이터베이스

  • 설치가 필요 없습니다. 파이썬에 기본으로 들어 있습니다.
  • DB 전체가 파일 하나(예: exam.db)입니다. 복사하면 백업, 지우면 삭제입니다.
  • 서버가 따로 없어 그 노트북 안에서만 쓰입니다. 교사 1인용 프로그램에 알맞습니다.
  • 스마트폰 앱, 웹 브라우저 등 많은 프로그램이 내부 저장소로 SQLite를 씁니다.
⚠️ DB 파일 = 학생 자료 묶음
활용 예시 프로그램의 exam.db에는 학번과 점수가 들어갑니다. 파일 하나라 옮기기 쉬운 만큼 메일·메신저·동기화 폴더로 새어 나가기도 쉽습니다. 보관 방법은 22장을 보세요. 또 DB 안에서 지운 자료는 파일 속에 흔적이 남을 수 있어, 완전히 지울 때는 파일째 지우는 것이 확실합니다.

# 지역 LLM(LM Studio 서버)에 질문 하나 보내기 — 파이썬 기본 기능만 사용
import json
import urllib.request

SERVER = "http://localhost:1234/v1"

# 1) 서버에 불러온 모델 이름 확인
with urllib.request.urlopen(SERVER + "/models", timeout=10) as res:
    model = json.load(res)["data"][0]["id"]
print("사용할 모델:", model)

# 2) 질문 보내기
question = "중학교 서술형 평가에서 부분점수 기준을 정할 때 주의할 점 3가지를 짧게 알려 줘. /no_think"
body = {"model": model,
        "messages": [{"role": "user", "content": question}],
        "temperature": 0.4, "max_tokens": 500}
req = urllib.request.Request(SERVER + "/chat/completions",
                             data=json.dumps(body).encode("utf-8"),
                             headers={"Content-Type": "application/json"})
print("큐웬이 답을 쓰는 중입니다. 잠시 기다리세요...")
with urllib.request.urlopen(req, timeout=900) as res:
    answer = json.load(res)
print(answer["choices"][0]["message"]["content"])

코드 읽기

  • SERVER — 14장에서 연 창구 주소입니다.
  • /models — 브라우저로 열어 본 그 주소에서 모델 이름을 가져옵니다.
  • messages — 채팅 창에 입력하던 질문입니다. question의 글을 바꿔 다시 실행해 보세요.
  • temperature, max_tokens — 3장의 온도, 답의 최대 길이(토큰)입니다.
  • /chat/completions — 질문을 보내고 답을 받는 창구입니다. 답은 choices[0].message.content에 들어 있습니다.
이 코드는 2026-10-27에 파이썬 3.13에서 실행해, LM Studio와 같은 형식으로 답하는 시험용 서버로부터 답을 받는 것까지 확인했습니다. 실제 LM Studio에서의 동작은 확인 필요입니다.
ConnectionRefusedError가 나오면 서버가 꺼진 것이고, IndexError가 나오면 서버에 불러온 모델이 없는 것입니다. 답 앞에 <think></think>가 붙어 나올 수 있는데, 생각 모드의 흔적이니 무시해도 됩니다.

# SQLite 데이터베이스 맛보기 — 파이썬 기본 기능만 사용 (가상 학번·가상 점수)
import sqlite3
from pathlib import Path

db_file = Path.home() / "practice.db"          # 예: C:\Users\내이름\practice.db
con = sqlite3.connect(db_file)

# 1) 표(테이블) 만들기: 학번 + 문항 번호가 겹치면 안 됨(기본 키)
con.execute("""CREATE TABLE IF NOT EXISTS scores(
                 sid TEXT, item INTEGER, score REAL,
                 PRIMARY KEY(sid, item))""")

# 2) 행(레코드) 넣기 — 같은 학번·문항이면 새 값으로 바꿈
rows = [("10101", 1, 4), ("10101", 2, 2.5),
        ("10102", 1, 3), ("10102", 2, 1),
        ("10103", 1, 2), ("10103", 2, 3)]
con.executemany("INSERT OR REPLACE INTO scores VALUES(?, ?, ?)", rows)
con.commit()

# 3) 질문(쿼리)하기 — 문항별 평균과 학생 수
print("문항, 평균 점수, 학생 수")
for row in con.execute("SELECT item, ROUND(AVG(score), 2), COUNT(*) FROM scores GROUP BY item"):
    print(row)

con.close()
print("저장한 파일:", db_file)

  4. student_results를 보면 ⑤ 생기부 초안의 근거가 된 성취기준별 득점·배점이 보입니다.
  5. SQL 실행 탭에서 아래 문장을 실행해 보세요. ③ 분석의 "득점률"과 같은 값이 나옵니다.
    SQL — 문항별 득점률(%)
    SELECT s.item_no AS 문항,
       ROUND(AVG(COALESCE(s.score, 0)) / i.max_pt * 100, 1) AS 득점률
FROM scores s JOIN items i ON i.exam_id = s.exam_id AND i.no = s.item_no
WHERE s.exam_id = 1
  AND s.sid NOT IN (SELECT sid FROM scores WHERE exam_id = 1
                    GROUP BY sid HAVING COUNT(score) = 0)
GROUP BY s.item_no ORDER BY s.item_no;
    (결시생 제외, 빈칸은 0점으로 계산 — 프로그램과 같은 규칙입니다. exam_id = 1은 첫 번째로 만든 시험입니다. 샘플 자료로 실행해 ③ 분석의 득점률 67.4 · 54.2 · 55.8 · 35.8 · 80.3 · 59.3과 똑같이 나오는 것을 확인했습니다.)
⚠️ 실제 자료의 DB는 고치지 마세요. DB Browser에서 값을 바꾸면 프로그램이 지키던 규칙(배점 초과 금지, 학번 중복 금지)을 건너뛰게 됩니다. 실제 학생 자료가 든 DB는 읽기 전용으로만 보고, 연습은 샘플 자료로 하세요.

24자주 묻는 질문

Q1. 지역 LLM은 챗GPT만큼 똑똑한가요?

아닙니다. 노트북에서 돌리는 4B 모델은 클라우드 AI보다 훨씬 작습니다. 짧은 초안·문체 바꾸기·정해진 형식의 반복 작업에 쓰고, 판단과 최종 확인은 교사가 합니다.

Q2. 인터넷을 끊어도 되나요?

설치(파이썬 라이브러리, LM Studio, 모델 내려받기)가 끝나면 인터넷 없이 모든 실습과 활용 예시가 동작합니다.

Q3. LM Studio 말고 다른 프로그램도 되나요?

OpenAI 형식 API를 제공하는 다른 프로그램(예: Ollama)도 원리는 같습니다. 활용 예시 프로그램은 LM Studio 기준(localhost:1234/v1)으로 만들었고, 왼쪽 연결 설정에서 주소를 바꿀 수 있지만 다른 프로그램으로는 확인하지 못했습니다.

Q4. 모델 파일에 학생 정보가 들어가나요?

아닙니다. 모델 파일은 내려받은 그대로이며, 대화한다고 모델이 학습하지 않습니다. 다만 LM Studio 채팅 기록은 노트북에 저장될 수 있으니 채팅 창에 학생 정보를 넣지 마세요.

Q5. DB 대신 엑셀로 저장하면 안 되나요?

사람이 보는 결과는 엑셀로 내려받을 수 있습니다. 프로그램 내부 저장은 중복·잘못된 값을 막고(기본 키·검사), 여러 시험을 학번으로 합치기 쉬운 DB가 알맞습니다.

Q6. 통계 숫자는 믿을 수 있나요?

통계는 파이썬이 계산합니다(큐웬 아님). 샘플 자료의 값을 별도 계산과 대조해 일치함을 확인했습니다. 점검 기준은 이 프로그램의 기본값이며 공식 기준이 아닙니다.

Q7. 다른 선생님 노트북에도 설치할 수 있나요?

네. 이 설명서 PART 2부터 같은 순서로 하면 됩니다. 프로그램은 교사 1인용이라 자료(data)는 노트북마다 따로입니다.

Q8. 모두 지우려면?

자료를 백업한 뒤 C:\exam_analyzer 폴더를 지우고, 파이썬·LM Studio·DB Browser는 설정 → 앱 → 설치된 앱에서 제거합니다. LM Studio 모델 파일은 My Models에서 지웁니다. 확인 필요
